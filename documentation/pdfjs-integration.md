# PDF.js Integration

Report Kit uses the PDF.js generic viewer for its live PDF preview.

The PDF.js distribution is bundled locally under:

```text
viewer/pdfjs/
````

This keeps PDF rendering and the preview UI fully local and avoids depending on an external PDF viewer or CDN.

## Report Kit Adapter

Report Kit integrates with the PDF.js generic viewer through a small adapter:

```text
viewer/pdfjs-adapter.js
```

The adapter is loaded by the PDF.js viewer and connects the viewer to the Report Kit preview server.

It:

* connects to the local preview server through WebSocket
* receives notifications when the generated PDF changes
* reloads the PDF through the PDF.js viewer API
* preserves the current page, zoom level, and scroll position across reloads

The reload mechanism uses PDF.js's existing history system rather than maintaining separate Report Kit viewer state.

## Modified PDF.js File

The upstream PDF.js `web/viewer.html` is intentionally modified to load the Report Kit adapter:

```html
<script type="module" src="/pdfjs-adapter.js"></script>
```

The modified file is located at:

```text
viewer/pdfjs/web/viewer.html
```

This is the only modification made to the PDF.js generic viewer UI.

The rest of the PDF.js distribution is kept as generated by the PDF.js build.

## Updating PDF.js

The `viewer/pdfjs/` directory contains a generated PDF.js generic build.

If the PDF.js version is upgraded or the distribution is regenerated, `viewer/pdfjs/web/viewer.html` will be replaced by the generated upstream version.

After regenerating the viewer, the Report Kit adapter script must therefore be added to `viewer.html` again:

```html
<script type="module" src="/pdfjs-adapter.js"></script>
```

The adapter itself lives outside the vendored PDF.js directory:

```text
viewer/
├── pdfjs/
│   └── ...
└── pdfjs-adapter.js
```

This separation makes it clear which files belong to PDF.js and which files belong to Report Kit.

## Preview Architecture

The live preview follows this flow:

```text
Report files
    │
    ▼
Chokidar
    │
    ▼
Preview build
    │
    ▼
Generated PDF
    │
    ▼
WebSocket notification
    │
    ▼
pdfjs-adapter.js
    │
    ▼
PDF.js viewer
```

When the report changes, the preview server rebuilds the content PDF and sends a `pdf-updated` message over the local WebSocket connection.

The adapter receives the message and reloads the document without refreshing the browser page.

Before replacing the document, the adapter records the current PDF.js navigation destination. After the new PDF has initialized, that destination is restored.

This allows the user to continue working at the same location in the report after every rebuild.

## Why the Adapter Is Separate

The adapter deliberately contains only the Report Kit-specific integration logic.

PDF.js remains responsible for:

* PDF rendering
* toolbar controls
* page navigation
* zooming
* scrolling
* search
* thumbnails
* bookmarks
* printing
* browser history integration

Report Kit is responsible only for:

* detecting report changes
* rebuilding the PDF
* notifying the viewer
* triggering the PDF reload
* preserving the current viewing position

This avoids maintaining a second custom PDF viewer or duplicating functionality already provided by PDF.js.
